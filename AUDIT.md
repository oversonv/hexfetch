# Аудит hexfetch

## Найденные причины и исправления

1. **Предупреждение `hexfetch.display.separator_length`.** Загрузчик YAML проверял `display` по белому списку полей, в котором `separator_length` отсутствовал. Поэтому корректное для пользователя поле считалось неизвестным и игнорировалось. Поле добавлено в схему `DisplayConfig`, валидируется как целое число `0..4096` (`0` означает автоматическую ширину), передаётся в renderer и сохраняется при сериализации конфигурации. Предупреждение не подавляется: некорректные значения по-прежнему дают диагностическое сообщение.

2. **Смещение значений при разных иконках и названиях модулей.** Renderer раньше складывал `key + separator + value` без расчёта ширины колонки ключа. Теперь он сначала вычисляет максимальную экранную ширину всех отображаемых ключей с учётом иконок, затем дополняет более короткие ключи пробелами. Измерение выполняется через существующий `logo.VisibleWidth`, который учитывает ширину Unicode-глифов и ANSI-последовательности.

3. **Отступ логотипа.** Встроенное значение и значение CLI-флага `--padding` были равны `1`, тогда как в приложенном сравнении Fastfetch оставляет на одну колонку больше. Значение по умолчанию изменено на `2`; явный `--padding` продолжает полностью переопределять его.

4. **Иконки и профиль Termux.** Персонального `$HOME/hex/hexfetch.yaml` в исходном ZIP не было. Поэтому исходные пользовательские значения иконок нельзя было исправить на месте. Добавлен `hex/hexfetch.yaml` с символами из предоставленного вывода Fastfetch: OS ``, Packages ``, Shell ``, Python ``, Terminal ``. Python настроен через имеющийся модуль `command`, поскольку отдельного модуля `python` в проекте нет.

5. **Оставшиеся различия в примере.** Termux-пакеты считаются по базе `dpkg`, но раньше подписывались как `pkg`; подпись приведена к `dpkg`, как в Fastfetch. Значение `TERM_PROGRAM=com.termux` раньше печаталось как есть; оно нормализуется в `Termux`.

## Проверки

- Все Go-файлы прошли `gofmt`.
- `git diff --check` прошёл без замечаний.
- `hex/hexfetch.yaml` успешно разобран YAML-парсером; проверены структура, список модулей и все пять иконок.
- Go unit tests и `go vet` выполнить не удалось в этой среде: проект требует Go `1.26`, установлен только Go `1.23.2`, а загрузка toolchain недоступна из-за отсутствия сетевого доступа. Поэтому успешный запуск тестового набора и новая сборка здесь не заявляются.

## Установка профиля

Скопировать профиль в ожидаемое приложением расположение:

```sh
mkdir -p "$HOME/hex"
cp hex/hexfetch.yaml "$HOME/hex/hexfetch.yaml"
```

После распаковки исходников пересобрать бинарник установленным Go 1.26:

```sh
CGO_ENABLED=0 go build -o hexfetch ./cmd/hexfetch
```

Исходный ZIP содержал старый локальный ELF-бинарник ARM64, который не включал внесённые изменения. Он не переносится в исправленный архив, чтобы его нельзя было случайно принять за новую сборку.
